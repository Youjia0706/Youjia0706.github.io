Hyperledger Fabric （官方 Sample 範例）

一、 Hyperledger Fabric

Hyperledger Fabric 是 Linux Foundation 推出的企業級區塊鏈框架，適合用於企業間的聯盟鏈（Permissioned Blockchain）。
它具有模組化設計、支持多通道、多組織、以及智能合約（Chaincode）功能。

  • Peer：節點，負責執行智慧合約及維護賬本。
  • Orderer：排序節點，負責交易排序與區塊打包。
  • Chaincode：智能合約，執行商業邏輯。
  • Channel：通道，不同組織間隔離的私有區塊鏈網路。
  • MSP：會員服務提供者，管理身份驗證。

二、環境準備

1. 安裝必要工具

確保 Docker 與 Docker Compose 已安裝，且服務已啟動。

2. 下載 Fabric 範例與工具

此指令會下載 fabric-samples 目錄、Fabric 二進位工具與映像檔。
此指令會自動拉取 Docker images，不用另外載
載下來的 fabric-samples 只要留這三個資料夾：

  1. bin:裡面是 peer, orderer, configtxgen, fabric-ca-client 等 binary 工具
  2. config:裡面是 core.yaml, orderer.yaml 的預設設定檔，可作為參考
  3. test-network: 官方簡易網路架構，可以參考其 docker-compose 與設定邏輯

三、啟動測試網路

1. 進入測試網路目錄

2. 啟動網路並建立通道

  • up：啟動 peer、orderer、CA 容器。
  • createChannel：建立通道。
  • -c mychannel：通道名稱為 mychannel。
  • -ca：使用 Fabric CA 產生憑證。

3. 確認容器狀態

你會看到 peer0.org1.example.com、peer0.org2.example.com、orderer.example.com、ca_org1、ca_org2 等容器運行中。

四、部署 Sample Chaincode：asset-transfer-basic

官方 Sample 中的 asset-transfer-basic 是用 Node.js 或 Go 寫成的範例智慧合約，管理簡單資產。

1. 部署 Chaincode

執行以下指令部署官方 sample chaincode：

  • -ccn basic：合約名稱為 basic
  • -ccp：chaincode 檔案路徑
  • -ccl go：使用 Go 語言撰寫

2. 部署成功會顯示相關安裝、核准、提交訊息。

五、設定環境變數，呼叫合約

1. 設定 Org1 Peer 環境變數

當你在使用 Hyperledger Fabric 的 sample 網路（例如 fabric-samples/test-network）時，需要設定這些環境變數來告訴 peer CLI：你是誰（用誰的身份）在呼叫哪一個 Peer。以下是詳細說明：

export CORE_PEER_TLS_ENABLED=true

  • 作用：啟用 TLS（Transport Layer Security）加密通訊。
  • 為什麼重要？：Fabric 節點預設會使用 TLS 保護通訊安全（例如 peer 和 orderer 間的連線），這個變數要設成 true 才能正確建立 TLS 連線。

export CORE_PEER_LOCALMSPID="Org1MSP"

  • 作用：指定當前 peer 所屬的組織的 MSP ID。
  • Org1MSP 是什麼？：在 configtx.yaml 和證書目錄裡，這是 Org1 的身份標誌。所有憑證都會標記 OU=Org1MSP。
  • 用途：peer CLI 執行交易時會依據這個變數決定使用哪一個組織的憑證。

export CORE_PEER_TLS_ROOTCERT_FILE=$PWD/organizations/peerOrganizations/org1.example.com/peers/peer0.org1.example.com/tls/ca.crt

  • 作用：指定 Peer 的 TLS 根憑證（CA 憑證），用來驗證連線對象的身份。
  • 用途：確保在連接 peer 時是連到真正的合法節點，而不是遭竄改的節點（防中間人攻擊）。

export CORE_PEER_MSPCONFIGPATH=$PWD/organizations/peerOrganizations/org1.example.com/users/Admin@org1.example.com/msp

  • 作用：指定執行指令的「使用者身份」。

  • 這裡是 Admin 的身份，所以這個 CLI 操作是以 Org1 的 Admin 角色發出指令。

  • 用途：

    • 當你用 peer chaincode invoke、peer lifecycle chaincode approveformyorg 時，這個 Admin 身份會對交易簽章。
    • 沒有 Admin 權限的身份就不能安裝或同意部署合約。

export CORE_PEER_ADDRESS=localhost:7051

  • 作用：指定要連線的 Peer 節點地址。

  • 7051 是 peer0.org1 的 gRPC 端口，你執行 chaincode 操作時會將交易請求送到這個節點上。

  • 用途：

    • 指定 peer CLI 命令要作用於哪一個 Peer 節點。
    • 例如 peer chaincode query 就會送給這個 Peer 執行查詢。
變數 說明
CORE_PEER_TLS_ENABLED 是否啟用 TLS 加密
CORE_PEER_LOCALMSPID 當前節點所屬 MSP ID
CORE_PEER_TLS_ROOTCERT_FILE TLS 憑證的根憑證位置
CORE_PEER_MSPCONFIGPATH 執行 CLI 操作時的使用者身份
CORE_PEER_ADDRESS 要連線的 Peer 節點地址

每次使用 peer CLI 前（或重新開機後）都需要先設定這些變數，否則會找不到身份或連不到節點。可以寫成 setOrg1Env.sh 這樣的 shell 檔快速載入。

2. 呼叫 Chaincode 新增資產

  • 這條指令會呼叫 basic 合約裡的 CreateAsset 函式，建立一個 ID 為 asset6，顏色為 yellow、擁有者為 Tom 等資產。

3. 查詢資產

會回傳資產詳細資料。

六、背書政策說明

1. 背書政策定義

背書政策（Endorsement Policy）決定哪些組織的 Peer 需要對交易背書（簽署），以確保交易有效且信任。

  • 預設 Sample 如 asset-transfer-basic 的背書政策通常是：

3. 呼叫時指定多 Peer 範例（符合多組織背書）

七、常見問題與排查

  • 交易 invoke 成功但 query 找不到資料？
    可能 invoke 尚未被區塊確認，或背書政策未滿足，造成交易無效。

  • 背書政策錯誤
    查看 peer log 會有 ENDORSEMENT_POLICY_FAILURE，確認 invoke 是否指定所有必要 peer。

  • 重新部署 Chaincode
    修改 chaincode 後需更新版本並重新部署。

八、補充說明名詞

名詞 說明
Peer 區塊鏈節點，執行合約和賬本狀態維護
Orderer 負責交易排序與打包成區塊
Chaincode 智慧合約，定義交易邏輯
Channel 通道，隔離不同組織的交易數據
MSP 會員服務提供者，身份管理機制
背書政策 決定哪些 Peer 必須簽署交易，確保可信
